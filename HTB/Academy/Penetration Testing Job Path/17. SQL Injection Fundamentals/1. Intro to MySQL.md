## Exercises

### Question 1 — Connect to the database using the MySQL client from the command line. Use the 'show databases;' command to list databases in the DBMS. What is the name of the first database?

The task gave me a target at `154.57.164.64:35674` and told me to authenticate with the user `root` and the password `password`.

#### First Attempt: Plain Connection

I started with a standard connection command, with the host and port flags added for the target.

```shell
┌──(—REDACTED—㉿kali)-[~]
└─$ mysql -u root -p -h 154.57.164.64 -P 35674
Enter password: 
ERROR 2026 (HY000): TLS/SSL error: SSL is required, but the server does not support it
```

**Breakdown:**

- `mysql` is the command-line client used to connect to a MySQL/MariaDB database
- `-u root` supplies the username, here `root`
- `-p` prompts for the password, so it stays out of the shell history
- `-h 154.57.164.64` sets the host to connect to, in place of the default localhost
- `-P 35674` sets the port to connect to. The `P` is uppercase, unlike the lowercase `p` used for the password

The line as a whole tries to log in as `root` on the target, entering the password at the prompt.

This was a dead end. The error says the client insisted on TLS/SSL while the server has no support for it, so the handshake failed before the password was even checked. The credentials were not the problem, and the plain connection command has no way around this on its own.

#### Second Attempt: Skipping SSL

The fix was to tell the client not to require SSL.

```shell
┌──(—REDACTED—㉿kali)-[~]
└─$ mysql -u root -p -h 154.57.164.64 -P 35674 --skip-ssl
Enter password: 
Welcome to the MariaDB monitor.  Commands end with ; or \g.
Your MariaDB connection id is 16
Server version: 10.7.3-MariaDB-1:10.7.3+maria~focal mariadb.org binary distribution

Copyright (c) 2000, 2018, Oracle, MariaDB Corporation Ab and others.

Type 'help;' or '\h' for help. Type '\c' to clear the current input statement.

MariaDB [(none)]> 
```

**Breakdown:**

- `--skip-ssl` turns off the client's SSL requirement, so it connects to a server that has no SSL support

The line as a whole is the same login as before with SSL switched off, and this time it got through.

The banner shows a MariaDB server (version `10.7.3`), and the same client and commands work for both MySQL and MariaDB. The prompt reads `MariaDB [(none)]>`, and `(none)` means no database is selected yet.

#### Listing the Databases

With a session open, I ran the statement the question asked for.

```shell
MariaDB [(none)]> SHOW databases;
+--------------------+
| Database           |
+--------------------+
| —REDACTED—         |
| information_schema |
| mysql              |
| performance_schema |
| sys                |
+--------------------+
5 rows in set (0.035 sec)
```

**Breakdown:**

- `SHOW databases` lists every database on the server
- `;` terminates the query. The client expects every command to end with a semicolon

The line as a whole returns the five databases on the server. I typed `databases` in lowercase, which works because SQL statements are not case sensitive.

The first database in the list is `—REDACTED—`. `information_schema`, `mysql`, `performance_schema`, and `sys` are the default system databases that come with the server, which leaves the first entry as the only one that holds application data.

**Answer:** `—REDACTED—`

> **Why it matters:** `--skip-ssl` is the fix to remember when a client demands TLS that the target does not offer. It is a common snag against lab and CTF targets.
