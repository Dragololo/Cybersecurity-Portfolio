#### Checking the Columns

The question refers to the `titles` table, so I described it to get the exact column names.

```shell
MariaDB [employees]> DESCRIBE titles; 

+-----------+-------------+------+-----+---------+-------+
| Field     | Type        | Null | Key | Default | Extra |
+-----------+-------------+------+-----+---------+-------+
| emp_no    | int(11)     | NO   | PRI | NULL    |       |
| title     | varchar(50) | NO   | PRI | NULL    |       |
| from_date | date        | NO   | PRI | NULL    |       |
| to_date   | date        | YES  |     | NULL    |       |
+-----------+-------------+------+-----+---------+-------+
4 rows in set (0.036 sec)
```

**Breakdown:**

- `DESCRIBE` lists a table's columns with their data types and properties
- `titles` is the table to inspect
- `;` terminates the query
- `Field` is the column name
- `Type` is the data type
- `Null` shows whether the column may be left empty. `NO` means required, and `YES` on `to_date` means it can be empty
- `Key` shows whether the column is part of a key. `PRI` appears on three columns (`emp_no`, `title`, and `from_date`), which means the primary key is made up of all three together
- `Default` is the default value, and `NULL` means none is set
- `Extra` shows extra properties such as `AUTO_INCREMENT`, and nothing is set here

The line as a whole shows four columns, and two of them matter for this question:

- `emp_no` is an integer holding the employee number
- `title` is a string of up to 50 characters holding the job title

The other two columns are `from_date` and `to_date`, which hold the start and end dates of each title.

> **Why it matters:** An employee can appear several times in `titles`, once for each title they have held. Because the primary key is a combination of three columns, the same `emp_no` can repeat as long as the title or the dates differ.

#### Running the Query

The question has two conditions joined by `OR`, so a record qualifies if either one holds.

```shell
MariaDB [employees]> SELECT * FROM titles WHERE emp_no > 10000 OR title != 'engineer'; 

+--------+-----------------+------------+------------+
| emp_no | title           | from_date  | to_date    |

| 10001  | Senior Engineer | 1986-06-26 | 9999-01-01 |
| 10002  | Senior Engineer | 1995-12-03 | 9999-01-01 |
—SNIP—
+--------+-----------------+------------+------------+

```

**Breakdown:**

- `SELECT *` returns every column
- `FROM titles` reads from the `titles` table
- `WHERE` begins the filter that decides which records are returned
- `emp_no > 10000` is the first condition, keeping records whose employee number is greater than 10000
- `OR` makes the record qualify if at least one of the two conditions is true
- `title != 'engineer'` is the second condition, keeping records whose title is not equal to `engineer`
- `;` terminates the query
- `—REDACTED— rows in set` is the number of records returned, which is the answer to the question

The line as a whole returns every record that satisfies at least one of the two conditions, and the row count at the bottom gives the number asked for.

Two points about the query:

- The `OR` means a record only needs one condition to be true. A record for employee `10001` with the title `Senior Engineer` passes on the employee number alone, even though it contains the word `engineer`.
- I wrote the second condition as `title != 'engineer'`, which is an exact match. It excludes only titles that are exactly `engineer`. The titles in this table are values such as `Senior Engineer`, so none of them equals `engineer` exactly, and this condition is true for every record.

The question asks about titles that do not _contain_ `engineer`, which would be written with `NOT LIKE '%engineer%'`. In this case the count came out as the accepted answer, so the query was enough, but the two conditions are not equivalent in general.
