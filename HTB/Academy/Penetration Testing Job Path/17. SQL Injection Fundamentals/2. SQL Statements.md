## Exercises

### Question 1 — What is the department number for the 'Development' department?

The target was `154.57.164.68:34530`, with the user `root` and the password `password`.

#### Connecting

I used the `--skip-ssl` flag from the start, since the server has no SSL support.

```shell
┌──(—REDACTED—㉿kali)-[~]
└─$ mysql -u root -p -h 154.57.164.68 -P 34530 --skip-ssl
Enter password: 
Welcome to the MariaDB monitor.  Commands end with ; or \g.
Your MariaDB connection id is 3
Server version: 10.7.3-MariaDB-1:10.7.3+maria~focal mariadb.org binary distribution

Copyright (c) 2000, 2018, Oracle, MariaDB Corporation Ab and others.

Type 'help;' or '\h' for help. Type '\c' to clear the current input statement.

MariaDB [(none)]> 
```

**Breakdown:**

- `mysql` is the command-line client used to connect to a MySQL/MariaDB database
- `-u root` supplies the username, here `root`
- `-p` prompts for the password, so it stays out of the shell history
- `-h 154.57.164.68` sets the host to connect to, in place of the default localhost
- `-P 34530` sets the port to connect to. The `P` is uppercase, unlike the lowercase `p` used for the password
- `--skip-ssl` turns off the client's SSL requirement, so it can connect to a server that has no SSL support

The line as a whole logs in as `root` on the target and prompts for the password. The prompt reads `MariaDB [(none)]>`, and `(none)` means no database is selected yet.

#### Finding the Right Database

The question names a department and gives no database, so I listed the databases first.

```shell
MariaDB [(none)]> SHOW DATABASES;
+--------------------+
| Database           |
+--------------------+
| employees          |
| information_schema |
| mysql              |
| performance_schema |
| sys                |
+--------------------+
5 rows in set (0.036 sec)
```

**Breakdown:**

- `SHOW DATABASES` lists every database on the server
- `;` terminates the query

The line as a whole returns five databases. `information_schema`, `mysql`, `performance_schema`, and `sys` are the default system databases, which leaves `employees` as the only one holding application data.

```shell
MariaDB [(none)]> USE employees; 

Reading table information for completion of table and column names
You can turn off this feature to get a quicker startup with -A

Database changed
```

**Breakdown:**

- `USE` switches the current session to the named database
- `employees` is the database to switch to. Database names are case sensitive
- `;` terminates the query
- `Reading table information for completion of table and column names` is the client building its tab-completion list for the new database. Starting the client with `-A` turns this off for a quicker startup

The line as a whole makes `employees` the current database, and the prompt changes to `MariaDB [employees]>`.

#### Checking the Columns

Before running a query against `departments`, I checked which columns it has so I would know the exact column names.

```shell
MariaDB [employees]> SHOW COLUMNS FROM departments; 

+-----------+-------------+------+-----+---------+-------+
| Field     | Type        | Null | Key | Default | Extra |
+-----------+-------------+------+-----+---------+-------+
| dept_no   | char(4)     | NO   | PRI | NULL    |       |
| dept_name | varchar(40) | NO   | UNI | NULL    |       |
+-----------+-------------+------+-----+---------+-------+
2 rows in set (0.036 sec)
```

**Breakdown:**

- `SHOW COLUMNS FROM` lists the columns of a table with their properties. It gives the same kind of information as `DESCRIBE`
- `departments` is the table to inspect
- `;` terminates the query
- `Field` is the column name
- `Type` is the data type
- `Null` shows whether the column may be left empty, and `NO` means it is a required field (the `NOT NULL` constraint)
- `Key` shows whether the column is a key. `PRI` is the primary key and `UNI` carries the `UNIQUE` constraint
- `Default` is the default value, and `NULL` means none is set
- `Extra` shows extra properties such as `AUTO_INCREMENT`, and nothing is set here

The line as a whole shows the table has two columns:

- `dept_no` is a four-character string and the primary key, so it identifies each department
- `dept_name` is a string of up to 40 characters, and its `UNIQUE` constraint means no two departments share a name

This confirmed that the department number lives in `dept_no` and the name in `dept_name`, which gave me what I needed for the query.

#### Running the Query

```shell
MariaDB [employees]> SELECT dept_no FROM departments WHERE dept_name = 'Development';

+------------+
| dept_no    |
+------------+
| —REDACTED— |
+------------+
1 row in set (0.035 sec)
```

**Breakdown:**

- `SELECT dept_no` returns only the `dept_no` column
- `FROM departments` reads from the `departments` table
- `WHERE dept_name = 'Development'` keeps only the rows whose `dept_name` equals the text `Development`. The string sits in single quotes
- `;` terminates the query
- `1 row in set` confirms exactly one record matched

The line as a whole returns the department number for the Development department. The `UNIQUE` constraint on `dept_name` explains why only one row can come back.
