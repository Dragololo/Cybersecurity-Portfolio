Took a short detour at this point to make sure I actually understood what `winrs` was doing and why Pass-the-Hash alone wasn't enough on its own — holding an identity locally on THMJMP2 isn't the same as having an open connection to THMIIS, so some remote-access tool still has to carry that identity over.

First attempt at using the hash, spawning `winrs` straight from the injected process:

```shell
mimikatz # sekurlsa::pth /user:t1_toby.beck1 /domain:za.tryhackme.com /ntlm:533f1bd576caa912bdb9da284bbc60fe /run:"winrs.exe -r:THMIIS.za.tryhackme.com cmd"
```

**Breakdown:**

- `/user:t1_toby.beck1` — the username to inject
- `/domain:za.tryhackme.com` — the domain that username belongs to
- `/ntlm:533f1bd576caa912bdb9da284bbc60fe` — the NTLM hash to inject in place of a password
- `/run:"winrs.exe -r:THMIIS.za.tryhackme.com cmd"` — the process to launch carrying that injected identity; `winrs.exe -r:THMIIS.za.tryhackme.com` opens a remote shell session on THMIIS, and `cmd` is the program to run once connected

No window came up for this one. At the time I wasn't sure why — figured it might be something to do with running over SSH rather than RDP, since there's no desktop for a spawned console to appear on. Confirmed afterwards that this was exactly it: `/run` launches the process on whatever window station the session has, and an SSH session has none, so there was never going to be a visible window to type into regardless of whether the command worked.
